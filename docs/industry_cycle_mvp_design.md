# 산업 사이클 추적기 MVP 설계

작성일: 2026-07-25  
상태: 아이디어 검증 완료, 구현 전 설계 기준선

## 1. 목표

한국과 미국의 중분류 산업을 대상으로 향후 3~12개월의 상대적 업황을 추적한다. 시스템은 미래 가격을 단정하지 않고, 산업이 5개 국면 중 어디에 있는지와 향후 6개월 동안 시장 대비 강할 가능성을 설명 가능한 점수로 제시한다.

국면은 다음과 같다.

1. 회복 초입
2. 확장
3. 과열
4. 둔화
5. 침체

사용자에게 제공할 행동 신호는 다음으로 제한한다.

| 국면/변화 | 기본 행동 |
|---|---|
| 회복 초입 확정 | 신규 매수 후보 |
| 확장 | 보유 또는 눌림목 관찰 |
| 과열 | 신규 매수 금지, 분할 익절 경고 |
| 둔화·하락 전환 | 회피 또는 가상 청산 |
| 신뢰도 부족·충돌 | 판정 보류 |
| 기준 통과 산업 없음 | 신규 추천 없음 |

공매도, 인버스, 레버리지, 자동 주문, 개인 보유 종목 맞춤화는 MVP 범위에서 제외한다.

## 2. 성공 기준

핵심 검증 질문은 다음과 같다.

> 회복 초입 신호가 발생한 산업 ETF가 이후 6개월 동안 해당 국가의 대표 시장지수보다 높은 수익률을 냈는가?

벤치마크:

- 한국: KOSPI
- 미국: S&P 500

저장할 성과 지표:

- 신호 후 1·3·6·12개월 절대수익률
- 같은 기간 벤치마크 대비 초과수익률
- 적중률: 6개월 초과수익률이 0보다 큰 신호의 비율
- 평균·중앙값 초과수익률
- 신호 후 최대상승폭과 최대하락폭
- 가상 포트폴리오 최대 낙폭
- 국면별 및 산업별 성과

성과가 검증되기 전에는 실전 매매 시스템으로 취급하지 않는다. 최소 2~3개월 동안 가상 신호를 운영하고, 6개월 성과는 데이터가 축적되는 대로 순차 확정한다.

## 3. 확정된 제품 범위

- 시장: 한국과 미국
- 분석 기간: 중기 3~12개월
- 산업 분류: 중분류 약 30~50개
- 세부 테마: HBM, 전력기기, 로봇, 원전 등은 산업 하위 태그로 관리
- 추천 계층: 산업 → ETF → 개별 종목
- 주간 출력:
  - 국가별 회복 초입 산업 최대 3개
  - 산업별 ETF 1~2개
  - 산업별 한국 종목 최대 3개, 미국 종목 최대 3개
- 정기 실행:
  - 데이터 수집 및 긴급 위험 검사: 매일
  - 공식 국면 판정: 주 1회
  - 통계 발표 반영: 발표 후 다음 수집 시점
  - 성과·오판 분석: 월 1회
- 전달 채널: HTML 대시보드, 텔레그램 주간·긴급 알림, 월간 HTML 리포트

3. 종목과 산업의 시점별 매핑

## 5. 데이터 원칙과 무료 우선 소스

### 5.1 원칙

- 원본 값, 관측 대상일, 최초 발표일, 수집일, 수정일을 분리 저장한다.
- 결측치는 0으로 채우지 않고 NULL로 유지한다.
- 백테스트는 `known_at <= signal_date`인 데이터만 사용한다.
- 공급자별 원본 식별자와 출처 URL을 저장한다.
- 무료 공급자와 유료 공급자는 같은 내부 레코드 형식으로 변환한다.
- 최신 데이터로 과거 신호를 다시 덮어쓰지 않는다.
- 주가와 ETF 가격은 분할·배당 등 기업행동 조정 여부를 명시한다.

> **`asset_price_daily`의 시점 계약 (Phase 1-A 수정)**: 위 `known_at <= signal_date` 원칙은
> `indicator_observation`(발표일이 있는 지표)에는 그대로 적용되지만, 일별 가격은 발표일 개념이
> 없고 거래일 자체가 곧 가격이 알려지는 기준일이므로 `asset_price_daily`에서는 `known_at`을
> 두 개로 분리한다: `available_at`(가격이 시장에서 이용 가능해진 시점 — `trade_date`만의
> 결정론적 함수, Yahoo 일봉은 보수적으로 거래일 종료 23:59:59 UTC)과 `collected_at`(우리
> 시스템이 실제 수집한 시각 — 감사·신선도 전용, 미래참조 차단에는 사용하지 않음). 이렇게 분리한
> 이유는 단일 `known_at`을 수집 시각(`now()`)으로 저장하면 2015년 가격을 2026년에 백필할 때
> `known_at=2026-...`이 찍혀 2026년 이전의 모든 as-of 백테스트에서 2015년 가격이 통째로
> 제외되고, 동일 가격을 재수집할 때마다 `known_at`이 계속 미래로 밀려 과거 조회 가능성이
> 영구히 사라지기 때문이다. 기존 `known_at` 컬럼은 유지하지 않고 제거했다(사용되지 않는
> 모호한 컬럼을 남겨 다시 잘못 참조되는 것을 방지) — 기존 레거시 행이 있다면 마이그레이션 시
> `available_at`/`collected_at` 모두 옛 `known_at` 값으로 보수적으로 채운다. 자세한 근거는
> `committee/core/database.py`의 `_migrate_asset_price_daily_split_known_at`과
> `committee/industry_cycle/price_repository.py` 모듈 docstring 참고.

### 5.3 유료 소스 도입 조건

아래 문제가 실제 성과나 운영 안정성을 제한한다고 확인될 때만 유료 소스를 검토한다.

- 과거 컨센서스 수정 이력이 없어 이익 전망 선행력을 검증할 수 없음
- 상장폐지·구성 종목 이력 누락으로 생존편향이 큼
- 한국과 미국의 산업 분류가 일관되지 않음
- 발표 당시 값과 이후 수정값을 구분할 수 없음
- 산업별 주문·재고·가동률 등 핵심 지표가 무료 소스에 없음
- 무료 API의 장애·호출 제한이 주간 운영을 반복적으로 방해함

## 6. 산업 분류

### 6.1 내부 표준

외부 분류체계 이름을 그대로 핵심 키로 사용하지 않는다. `industry_id`를 가진 프로젝트 내부 표준을 만들고 각 외부 분류와 종목을 매핑한다.

초기 예시:

- 반도체
- 하드웨어·전자부품
- 소프트웨어·클라우드
- 통신서비스
- 자동차·부품
- 조선
- 기계·산업재
- 항공·방산
- 운송·물류
- 화학
- 철강·비철금속
- 건설·건자재
- 전력·유틸리티
- 에너지
- 은행
- 보험
- 증권
- 부동산
- 헬스케어·바이오
- 필수소비재
- 경기소비재
- 미디어·엔터테인먼트

구현 시 실제 ETF와 기업 커버리지를 확인해 30~50개로 확장한다. 산업 수를 억지로 채우지 않으며, 대표 ETF나 핵심 데이터가 없는 산업은 `coverage_status=INSUFFICIENT`로 둔다.

### 6.2 테마

테마는 산업과 별도 점수를 만들지 않고 다음 구조로 연결한다.

`theme → parent_industry → related_etfs/stocks`

테마 뉴스가 급증해도 상위 산업의 중기 신호가 약하면 `단기 관심/중기 미확인`으로 표시한다.

## 7. 점수와 국면 판정

### 7.1 산업 기본 점수

모든 하위 점수는 0~100으로 정규화한다.

```text
cycle_score =
    0.25 * fundamentals_score
  + 0.20 * earnings_revision_score
  + 0.20 * relative_strength_score
  + 0.15 * flow_score
  + 0.10 * macro_fit_score
  + 0.10 * breadth_score
```

초기 가중치는 가설이며 설정 파일로 분리한다. 데이터가 없는 항목은 0점 처리하지 않고, 사용 가능한 항목의 가중치를 다시 합이 1이 되도록 정규화한다. 단, 데이터 완전성 점수를 별도로 낮춘다.

하위 점수:

- `fundamentals_score`: 생산, 출하, 재고, 신규주문, 수출, 원자재 투입비용
- `earnings_revision_score`: 매출·이익·EPS 전망의 상향 비율과 변화 속도
- `relative_strength_score`: 산업 ETF의 3·6·12개월 벤치마크 대비 성과
- `flow_score`: 거래대금, 기관·외국인 누적 수급, ETF 자금 흐름
- `macro_fit_score`: 금리, 달러, 유가, 신용스프레드 등과 산업의 역사적 민감도
- `breadth_score`: 산업 내 상승 종목 비율, 200일선 상회 비율, 실적 개선 기업 비율

### 7.2 과열과 위험

사이클 점수와 별개로 `overheat_score`와 `risk_score`를 계산한다.

과열 예시:

- 장기 추세 대비 가격 이격
- 단기 수익률의 역사적 백분위
- 거래대금 급증
- 밸류에이션의 산업 역사 대비 백분위
- 뉴스·검색 관심 급증

위험 예시:

- 이익 전망 하향 전환
- 상대강도와 시장 폭 동반 붕괴
- 핵심 산업 통계의 전월·전년 동반 악화
- 신용·유동성 충격
- 정책·공급망·실적 쇼크

### 7.3 국면 상태기계

단순 점수 구간만 사용하지 않고 점수 수준, 변화율, 확인 기간을 함께 사용한다.

| 현재 조건 | 후보 국면 |
|---|---|
| 낮은 수준에서 점수 상승, 선행지표 개선 | 회복 초입 |
| 높은 점수와 양의 변화율 유지 | 확장 |
| 높은 사이클 점수 + 높은 과열 점수 | 과열 |
| 점수 하락과 선행지표 악화 | 둔화 |
| 낮은 점수와 음의 변화율 지속 | 침체 |

확정 규칙:

- 회복 초입: 2주 연속 조건 충족
- 과열: 첫 주 관찰, 다음 주에도 유지되면 익절 경고
- 하락 전환: 2주 연속 악화
- 실적 쇼크·급락·정책 충격: 확인 기간 없이 긴급 경고
- 상태 변경 사유와 기여 지표를 매번 저장

최종 신뢰도:

```text
confidence =
    signal_strength
  * data_completeness
  * history_reliability
  * model_agreement
```

신뢰도가 기준 미만이면 국면은 표시할 수 있지만 행동 추천은 `판정 보류`로 제한한다.

## 8. ETF와 종목 후보

### 8.1 ETF

산업 신호와 ETF 품질을 분리한다.

ETF 필터:

- 산업 대표성
- 평균 거래대금과 스프레드
- 순자산 규모
- 운용 보수
- 레버리지·인버스 여부
- 산업 외 노출 비중
- 상장 이력

ETF가 없는 산업은 개별 종목 바스켓을 지표로 사용할 수 있으나, ETF 추천은 `없음`으로 표시한다.

### 8.2 종목

종목 점수 예시:

```text
stock_score =
    0.30 * earnings_quality
  + 0.25 * estimate_revision
  + 0.20 * relative_strength
  + 0.15 * financial_health
  + 0.10 * liquidity
  - risk_penalty
```

제외 조건:

- 거래정지·관리·상장폐지 위험
- 국가별 유동성 하위 구간
- 상장 이력 부족
- 자본잠식 또는 중대한 재무 위험
- 지속 적자와 현금흐름 악화가 동시에 발생
- 중기 추세 대비 과도한 급등
- 데이터 완전성 기준 미달

추천 수를 채우기 위해 기준 미달 종목을 포함하지 않는다.

## 9. 제안 데이터 모델

기존 DB에 다음 테이블을 추가한다. 이름은 구현 시 마이그레이션 충돌 여부를 다시 확인한다.

| 테이블 | 목적 | 핵심 키/필드 |
|---|---|---|
| `industry_master` | 내부 산업 표준 | `industry_id`, 국가 범위, 이름, 활성 상태 |
| `industry_alias` | 외부 분류 매핑 | 공급자, 외부 코드, `industry_id`, 유효기간 |
| `industry_asset_map` | 산업-ETF-종목 매핑 | 자산, 산업, 가중치, `valid_from/to` |
| `theme_industry_map` | 테마-산업 연결 | `theme_id`, `industry_id`, 유효기간 |
| `indicator_catalog` | 지표 정의 | 공급자, 시리즈 ID, 단위, 빈도, 변환식 |
| `industry_indicator_map` | 산업별 지표 구성 | 산업, 지표, 방향, 가중치 |
| `indicator_observation` | 원본·시점 기준 관측값 | 관측일, 값, 발표일, 수집일, 빈티지 |
| `asset_price_daily` | KR/US/ETF 공통 가격 | 자산 ID, 거래일, OHLCV, 조정주가 |
| `industry_factor_weekly` | 주간 하위 점수 | 산업, 주차, 6개 요인, 완전성 |
| `industry_cycle_signal` | 국면과 행동 신호 | 산업, 주차, 국면, 점수, 신뢰도, 확정 여부 |
| `industry_signal_reason` | 설명 가능한 기여도 | 신호, 지표, 기여점수, 근거 |
| `industry_candidate` | ETF·종목 후보 | 신호, 자산, 순위, 점수, 제외 사유 |
| `signal_performance` | 사후 성과 | 신호, 기간, 절대/상대수익, MFE/MAE |
| `cycle_model_config` | 버전별 가중치·임계값 | 버전, JSON 설정, 활성일 |
| `data_quality_event` | 누락·지연·수정 기록 | 공급자, 대상, 심각도, 상태 |

모든 신호에는 `model_version`과 `data_cutoff_at`을 저장한다. 그래야 나중에 점수식을 바꿔도 당시 판단을 재현할 수 있다.

## 11. 출력 설계

### 11.1 대시보드

필수 화면:

1. 한국·미국 산업 사이클 히트맵
2. 산업별 현재 국면, 전주 대비 변화, 신뢰도
3. 점수 구성과 상위 긍정·부정 기여 지표
4. 대표 ETF 및 종목 후보
5. 과열·하락 전환 목록
6. 데이터 완전성·지연 상태
7. 과거 신호와 1·3·6·12개월 성과
8. 가상 포트폴리오와 벤치마크 비교
9. 모델 버전과 임계값 변경 이력

동일 산업에 대해 단기·스윙·장기 점수는 MVP에서 계산하지 않는다. 향후 확장 공간만 스키마에 남긴다.

### 11.2 텔레그램

주간 메시지:

- 새롭게 확정된 회복 초입 산업
- 기존 회복 신호의 유지·해제
- 과열 및 하락 전환
- ETF·종목 후보와 핵심 근거
- 추천 없음 또는 데이터 부족 여부

긴급 메시지:

- 실적 쇼크
- 핵심 선행지표 급락
- 산업 ETF 급락과 시장 폭 붕괴
- 데이터 장애로 기존 신호 신뢰도가 크게 하락

### 11.3 월간 리포트

- 한 달간 발생·해제된 신호
- 이전 신호의 상대수익률
- 가장 잘 맞은 산업과 가장 크게 틀린 산업
- 오판에 기여한 지표
- 데이터 누락과 공급자 장애
- 모델 변경 제안

자동으로 가중치를 변경하지 않는다. 변경안은 백테스트와 승인 후 새 `model_version`으로 적용한다.

## 12. 구현 순서

### Phase 0 — 기준선과 데이터 계약

1. 내부 산업 분류 1차 목록 작성
2. ETF·종목·외부 분류 매핑 포맷 확정
3. 신규 DB 테이블과 마이그레이션 테스트
4. `known_at`, `observed_at`, `vintage_at` 규칙 확정
5. 데이터 품질 리포트 작성

완료 조건: 동일 입력으로 같은 산업·지표 매핑을 재현할 수 있다.

### Phase 1 — 가격 기반 최소 엔진

1. 한국·미국 산업 ETF와 벤치마크 가격 백필
2. 공통 `asset_price_daily` 구축
3. 3·6·12개월 상대강도와 변동성 계산
4. 과열·추세 훼손 점수 계산
5. 가격만 사용하는 임시 국면을 대시보드에 표시

완료 조건: 데이터 누수 없이 주간 산업 순위와 과거 6개월 상대수익을 계산한다.

### Phase 2 — 산업 펀더멘털

1. FRED/ALFRED 산업 시리즈 카탈로그
2. KOSIS/ECOS 산업 통계 카탈로그
3. 산업별 생산·출하·재고·주문·수출 점수
4. 발표일·빈티지 기준 백테스트
5. 데이터 완전성과 지연 패널티

완료 조건: 회복 초입 신호마다 최소 2개 이상의 비가격 근거가 있다.

### Phase 3 — 실적·시장 폭·후보 추천

1. 종목-산업 매핑
2. 산업 내 실적 개선 비율과 컨센서스 변화
3. 산업 내 상대강도·상승 종목 비율
4. ETF 품질 필터
5. 유동성·재무 위험 필터를 적용한 종목 랭킹

완료 조건: 산업, ETF, 종목 점수가 분리되고 모든 제외 사유가 조회된다.

### Phase 4 — 운영 채널과 모의 운용

1. 주간 상태기계와 2주 확인 규칙
2. 텔레그램 주간·긴급 알림
3. 월간 HTML 리포트
4. 가상 포트폴리오
5. 2~3개월 모의 신호 운영

완료 조건: 과거 신호를 덮어쓰지 않고 매주 성과가 누적된다.

### Phase 5 — 검증 후 개선

1. 워크포워드 검증
2. 산업·국면별 임계값 민감도 분석
3. 무료 데이터 병목 확인
4. 필요한 경우에만 유료 소스 비교 시험
5. 규칙 모델을 기준선으로 유지한 채 확률 모델 추가

완료 조건: 새 모델이 비용과 복잡도를 감안해 규칙 기준선보다 일관되게 낫다.

## 13. 테스트 전략

### 단위 테스트

- 결측치를 0으로 오인하지 않음
- 가중치 재정규화
- 지표 방향성 반전
- 국면 전환과 2주 확인 규칙
- 긴급 경고 우선순위
- 국가별 유동성 백분위
- 추천 수를 억지로 채우지 않음

### 데이터 테스트

- 자산별 날짜 중복
- 발표일이 관측일보다 비정상적으로 빠른 행
- 미래 날짜 데이터
- 조정주가 불연속
- 산업 매핑 유효기간 겹침
- 공급자별 결측률과 갱신 지연

### 백테스트 테스트

- 신호일 이후 가격만 성과 계산에 사용
- 당시 공개되지 않은 통계·재무·컨센서스 제외
- 상장폐지와 종목 교체 반영
- 거래일 달력과 국가별 휴장 처리
- 모델 버전별 결과 재현

### 통합 테스트

- 일간 수집 실패가 기존 야간 파이프라인을 중단하지 않음
- 주간 판정 재실행이 멱등적임
- 대시보드 데이터가 없어도 빈 상태를 정상 렌더링
- 텔레그램 중복 알림 방지
