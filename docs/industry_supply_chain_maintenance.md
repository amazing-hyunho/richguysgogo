# 소부장 지도 운영

원본은 `config/industry_supply_chains.json`입니다. 25개 활성 산업은 기존 산업 ID를 그대로 사용합니다. 디스플레이는 하드웨어·전자부품 지도에 포함합니다. 신규 산업을 사이클 분류에 추가할 때 지도에도 해당 ID와 조사 순서를 추가해야 검증이 통과합니다.

기업 마스터, 출처, 제품·산업 관계를 분리합니다. 한 기업의 서로 다른 제품은 별도 관계로 기록합니다. 동일 기업이 여러 산업에 등장하는 것은 매출 비중을 여러 번 배분했다는 뜻이 아닙니다.

공식 제품 페이지·공시·기업 IR에서 확인한 짧은 사실 요약만 `fact`에 기록합니다. `cycle_hypothesis`는 검증 전 가설로 유지합니다. 투자 후보 점수와 사이클 판정에는 자동 가산하지 않습니다. 역할은 소재·부품·장비·서비스로, 최종 산업까지의 연결은 직접·간접으로 구분합니다. 원전 정비처럼 장비와 서비스가 결합된 경우 제품명에 함께 명시합니다.

개별 해외 고객·경쟁사·상위 공급사는 출처와 자료 기준일이 있는 경우만 `external_links`에 기록합니다. 로고나 업계 순위표만으로 납품계약을 단정하지 않습니다. 현재 기업과 분할 전 기업, 상장 모회사와 비상장 자회사를 혼동하지 않습니다. 최초 기업 코드는 로컬 `ticker_master`와 대조했으며, 이후 종목 매수 후보로 사용할 때는 상장·거래 상태를 다시 확인해야 합니다.

날짜 없는 제품 페이지는 `published_at`·`data_as_of`를 null로 둡니다. `accessed_at`은 실제 확인일이고 `known_at`은 이번 연구에서 알게 된 날입니다. 과거 사업보고서의 관계는 과거 사실로 표시합니다. 최신 근거로 교체할 때 기존 근거를 지우지 말고 새 관계 버전/출처를 추가하는 확장이 필요합니다. 현재 v1은 초기 관측 저장이며 완전한 시점별 계약 이력 DB가 아닙니다.

## 순차 조사

대시보드의 01~25 순서로 각 지도에 핵심 공정별 기업을 늘립니다. 첫 심화 대상은 건설기계의 유압·하부주행체입니다. 이후 반도체·전자부품, 자동차, 조선·LNG, 전력·원전, 나머지 제조업과 서비스업 순입니다.

각 기업에 최신 사업보고서의 제품별 매출, 고객 집중도, 인증·양산 상태를 추가합니다. 제품 매출과 산업별 매출은 다르므로 합산 공시를 개별 산업 비중으로 쪼개지 않습니다. 지표는 현재 이름만 등록한 조사 계획이며 관측값은 아직 연결하지 않았습니다. 실제 시계열을 확보한 후 기업 수주·매출과 비교해 시차·반증을 검증합니다.

## 재생성 및 확인

```powershell
python scripts/build_supply_chain_report.py
python scripts/render_dashboard_for_pages.py
python -m unittest discover -s tests -p test_supply_chain.py
```

일반 `scripts/build_dashboard.py` 실행과 Pages 렌더링 모두 최신 지도 JSON을 탑재합니다. 웹 요청은 지도 로딩 시 발생하지 않으며 저장된 근거만 사용합니다. 기존 임베디드 시장 데이터로 재렌더링하면 시장 데이터의 기준일은 보존됩니다. 지도 확인일과 시장 데이터 기준일을 혼동하지 않습니다.

현재 산출물은 초기 지도이며 모든 산업·기업의 심층조사 완료가 아닙니다. 외부 알림은 설정하지 않았습니다.

## 재무·뉴스·매크로 추적

`python scripts/refresh_supply_chain_monitor.py --execute`로 기업별 DART 주요 계정, 기업명 기반 RSS 뉴스, 금리·환율·원가 뉴스와 기존 DB의 산업 뉴스·매크로를 갱신합니다. `--skip-news`·`--skip-financials`로 네트워크 수집을 각각 생략할 수 있습니다. 기본 실행은 dry-run입니다.

기존 `sync_weekly.py`의 산업 배치에 갱신 단계를 연결했습니다. 산업 매크로 백필과 산업 뉴스 수집 이후, 대시보드 빌드 전에 실행됩니다. 별도의 새 예약 작업은 만들지 않았으므로 기존 주간 배치가 실제로 실행되어야 갱신됩니다. 단독 갱신 후에는 `python scripts/render_dashboard_for_pages.py`로 화면에 반영합니다.

최신 결과는 `data/supply_chain_monitor.json`, 매 실행 이력은 `runs/YYYY-MM-DD/supply_chain/시각.json`에 보존합니다. 뉴스 첫 발견일은 재수집해도 유지하며 최근 28일 자료를 표시합니다. 수집 오류와 기사 없음은 구분하고, 재무 갱신 실패 시 이전 성공 자료와 최근 실패 상태를 함께 표시합니다. 기사 제목의 사건 분류는 본문 사실 확인이나 투자 판단을 대신하지 않습니다. 동명이인 기업은 별칭과 제외 키워드로 관리합니다.

DART 반기·3분기 손익은 `thstrm_add_amount`가 있으면 누적값을 사용합니다. 재무제표는 연결을 우선하고 없으면 별도를 명시합니다. 매출·이익 비교는 전년 동기, 자산·부채 비교는 전기말입니다. 전기값이 음수 또는 0이면 증감률은 계산하지 않습니다. 합병·사업부 변경에 따른 비교가능성은 별도 검토해야 합니다. 원시 계정과 접수번호를 저장합니다.

산업 지표 DB는 이미 전년비·전기비 변환된 값입니다. 원자료 단위와 구분해 값은 %, 직전 관측 대비 증감은 %p로 표시합니다. FRED 원자료 링크와 DB의 관측일·발표일을 표시하며, 한국 기업 수요를 대신하는 미국·글로벌 대리지표라는 한계를 표시합니다. 공통 `daily_macro`는 원출처·지표별 발표시각이 충분히 보존되지 않아 해당 한계를 별도 표시합니다. 신규 매크로 네트워크 수집은 기존 산업 배치가 담당합니다.

수동 공시 정량 조사는 `companies[].research_observations`에 기간·범위·단위·출처와 함께 저장합니다. 예를 들어 동진쎄미켐의 반도체 부문 매출을 포토레지스트·CMP 각각의 매출로 배분하지 않습니다. 제품별 매출이 없으면 기존 null을 유지합니다.
