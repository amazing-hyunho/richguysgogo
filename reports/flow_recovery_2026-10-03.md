# 외국인 수급 수집 복구 — 2026-10-03

기존 Naver HTML 수집 주소가 종료된 뒤 수급이 9월 17일에서 멈춰 있었다. 새 Naver 투자자별 매매동향 페이지의 공개 JSON 요청을 확인하고 수집기를 교체했다.

- 원천: `https://stock.naver.com/api/domestic/market/trend/daily`
- 범위: `tradeType=KRX`, `marketType=KOSPI/KOSDAQ`. NXT 합산 자료가 아니다.
- 원천 금액 단위는 원. 기존 스냅샷 계약에 맞춰 시장별 억원 단위로 반올림한다.
- 외국인은 Naver 화면과 동일하게 `9000 + 9001`(기타외국인 포함). 기관계는 8개 기관 분류의 합계이며 기타법인은 제외한다.
- 두 시장의 날짜 일치, 필수 투자자 분류, 숫자 유효성, 중복·미래 날짜를 확인한다. 검증 실패나 수집 실패 시 새 동기화 단계는 실패 종료하며 DB 쓰기를 시작하지 않는다.

## 복원 내역

원천이 제공한 2026-05-08~2026-10-02의 최근 100거래일을 다시 저장했다. 누락만 채운 것이 아니라 이 기간의 기존 장중 값도 원천의 현재 일별 값으로 갱신했다. 9월 18일 이후 비어 있던 실제 거래일 9개가 복구됐다. 원천에 없는 휴장일을 임의로 채우지 않았다.

20·60거래일 누적은 원천의 거래일 목록으로 계산했다. 조회 범위 초반에 필요한 과거 관측 수가 부족한 날짜의 누적은 NULL이며 최신 누적은 완전하다. 복원 전 전체 DB는 `%TEMP%/investment-before-flow-repair-20261003.db`에 백업했다.

## 재발 방지 및 검증

- `sync_all.py`가 새 `sync_market_flows.py`를 실행한다. 기본은 전일까지의 최근 100거래일로, 미완료 당일 세션을 제외한다.
- 주말·휴일 수집 시 실제 거래일로 저장한다. 토요일에 금요일 값을 토요일 수급으로 복제하지 않는다.
- 과거 날짜의 누적 계산에 미래 행이 들어가지 않도록 날짜 상한을 적용했다. 결측 창으로 인해 이미 검증된 누적값이 NULL로 지워지지 않도록 했다.
- 대시보드의 시장별 수급 카드와 전일 비교는 복원된 DB를 우선 사용한다.
- 관련 테스트 42개 통과, 생성 HTML JavaScript 구문 검사 통과, DB quick_check 통과.
- 10월 3일 실제 자동 실행 스냅샷에서도 10월 2일의 정상 수급을 확인했다.
- GitHub Pages 배포 성공 및 공개 HTML에 동일한 날짜·금액이 포함된 것을 확인했다. 실제 브라우저 시각 검증은 별도로 수행하지 않았다.
- 전체 지표 감사 결과: 최근 저장값 57개, 지연 0개, 미수집 1개(PMI). 이 결과는 저장일 기준이며 미래 원천 서비스 가용성을 보장하지 않는다.

수집 응답과 비교 가능한 정규화 이력은 `runs/market_flow/latest.json`에 저장한다. 수동 재실행은 `python scripts/sync_market_flows.py`, 쓰기 없는 확인은 `python scripts/sync_market_flows.py --dry-run`이다.
